Control the action before the agent executes it.

HamidCognition Action Gate is a deployable control boundary between an AI agent and protected tools. It evaluates an action, binds authorization to its execution context, records evidence, and permits execution only through the governed path.

Product

A narrow boundary for a hard problem.

Action Gate asks whether the protected tool can independently verify that this exact agent action is authorized, correctly bound, current enough for the governed path, and not being replayed.

Decision integrity

Decisions are bound to tenant, actor, session and action context, with cryptographically bound records.

Execution authority

Gate-issued authority is required at the protected execution boundary. A boolean “authorized” flag is not the boundary.

Replay resistance

Single-use nonces and persistent authority state prevent the same execution authority from crossing the barrier twice.

Fail-closed evidence

If required evidence or execution reservation cannot be established, the governed path does not silently become permissive.

HTTP + MCP

The same governed authority model can protect HTTP and MCP tool paths rather than treating transport as the security boundary.

PostgreSQL persistence

Production operation supports persistent state so decisions and authority nonce state survive service restarts.

What can be reconstructed?

The implemented evidence record includes agent, tenant, actor, session, normalized action, action hash, policy snapshot/hash, nonce, risk assessment, decision, timestamps, execution outcome and evidence hashes.

Replay is verification, not theatre.

The acceptance procedure requires replay after restart to reproduce stored decisions and hashes. A passing demo alone is not treated as a customer security acceptance.

Security Boundary

Fail closed where authorization cannot be established.

These are documented product boundaries, not a promise of universal AI safety, policy correctness, regulatory certification or downstream correctness.

Tenant isolation

Cross-tenant decision retrieval and execution are rejected when the binding does not match.

Action binding

The action hash must match the execution request at the protected boundary.

Policy binding

A mismatched or missing policy binding is rejected fail-closed.

Nonce protection

Consumed authority cannot be reused, including after protected-tool restart.

Direct-access rejection

Protected endpoints and tools reject calls that arrive without Gate-issued execution authority.

Evidence failure

If execution cannot be reserved or recorded as required, the downstream call is not treated as authorized.
