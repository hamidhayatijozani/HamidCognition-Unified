# Action Gate Pricing and Scope

## Commercial purpose

This document defines a concrete first transaction without pretending that a repository is a sales department.

The initial offer is a **30-day one-tool proof-of-value pilot**. It is intentionally narrow so the buyer can test the execution boundary against a real protected tool before discussing broader deployment.

## Pilot price

**Proposed pilot fee: USD 7,500–10,000 for 30 days.**

This is a commercial proposal, not a claim that a market transaction has already occurred.

The final quote is selected within this band according to integration complexity, number of protected paths, customer support requirements and acceptance scope.

## Pilot includes

- one protected HTTP or MCP tool;
- one Action Gate deployment;
- tenant / actor / session / action binding;
- ALLOW / DENY / ASK / SANDBOX policy cases;
- direct-bypass testing;
- authority expiry testing;
- replay testing;
- tampering tests;
- persistence/restart validation;
- evidence review;
- customer acceptance report;
- release and source provenance record.

## Pilot excludes

- organization-wide rollout;
- custom agent framework development;
- unrestricted security consulting;
- regulatory certification;
- 24/7 support;
- guaranteed business or financial outcomes;
- protection of tools that were not included in the agreed acceptance scope.

Additional work is separately scoped.

## Conversion after pilot

A successful pilot can convert to:

**SELF_HOSTED** — licensed deployment operated by the customer, with separately scoped support.

**MANAGED** — service operated by HamidCognition, subject to infrastructure, security and support scope.

**ENTERPRISE** — negotiated integration, deployment architecture, security review, support and SLA.

No fixed annual price is asserted here until the deployment responsibility and support scope are known.

## Payment and acceptance

The commercial sequence is:

**Scope → Quote → Written agreement → Payment request → Settlement verification → Deployment → Acceptance → Entitlement**

The repository payment policy currently specifies USDT settlement. The operator must supply the actual receiving address and network policy outside source control.

A transaction is recorded only with the corresponding transaction hash and required confirmation evidence.

## Buyer-facing claim

Use:

> "Protect one high-impact agent tool with an enforceable authorization boundary and prove the tested behavior."

Do not use:

- "guaranteed safe AI";
- "compliance certified";
- "prevents every prompt injection";
- "zero-risk agents";
- "proven to increase ROI by X%".

## First-deal rule

Do not enlarge the first deal to compensate for lack of customers. The first objective is one paid, bounded, reproducible acceptance result.

That creates three independent records:

1. engineering evidence;
2. customer acceptance evidence;
3. revenue evidence.

Only after all three exist should the transaction be described as a customer deployment.
