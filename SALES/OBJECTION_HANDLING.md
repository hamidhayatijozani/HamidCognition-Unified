# Sales Objection Handling

## “We already have an AI security platform.”
Positioning: Action Gate is a dedicated execution-control boundary, not a replacement. The integration question is whether the existing platform can supply policy/security context to a point immediately before tool execution.

## “Why do we need another control point?”
Focus the discussion on separation of authorization from the agent runtime. The buyer can evaluate whether independent enforcement, single-use authorization, and execution evidence address a gap in the current architecture.

## “Can we build this ourselves?”
Yes, a buyer can build any control plane internally. The commercial discussion should compare engineering time, integration risk, operational ownership, evidence/replay requirements, and the time needed to reach a controlled production deployment.

## “Is this an AI safety product?”
Use precise language: pre-execution authorization and evidence for AI agent actions. Do not broaden the claim into universal AI safety.

## “Does it guarantee compliance?”
No. It can provide controls and evidence relevant to a customer's governance program, but regulatory compliance is jurisdiction-, system-, and requirement-specific.

## “Does it work with MCP?”
The commercial product includes MCP enforcement. A PoV should validate the customer's exact MCP topology and deployment constraints.

## “Can we run it on-premises?”
The commercial deployment model includes self-hosted options, subject to the agreed package and support scope.

## “What is the pilot supposed to prove?”
One concrete agent-to-tool path: authorization before execution, identity/context binding, enforcement behavior, evidence capture, replay, and agreed acceptance criteria.

## “Why is the pilot $50K?”
The figure is an indicative commercial starting point for a scoped enterprise PoV, not a claim about every engagement. Scope, integration, support, data requirements, and procurement constraints can change the final price.
