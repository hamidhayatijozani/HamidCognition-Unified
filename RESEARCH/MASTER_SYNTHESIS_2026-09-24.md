# Master Research Synthesis — 2026-09-24

## Purpose
این سند، متن ثبت‌شدهٔ تحلیل تلفیقی خطوط پژوهشی پروژه است. هدف آن حفظ یک تصویر واحد از ایده‌ها، سازوکارهای مشترک، مرز شواهد و مسیر آزمون است؛ نه اعلام اولویت علمی یا نتیجهٔ اثبات‌شده.

## Central research hypothesis
مهم‌ترین فرضیهٔ مشترک این بدنه این است:

> ممکن است واحد بنیادی یک سیستم شناختی، پاسخ یا ادعا نباشد؛ بلکه «انتقال قابل‌ردیابی از یک وضعیت به وضعیت دیگر» باشد.

این گزاره فعلاً HYPOTHESIS است.

## Four research cores
1. Epistemic State Transition / Liquidity
2. Evidence–Claim Provenance + Epistemic Distance
3. Observable Decision Governance
4. Dynamic State + Memory + Regime Transition Architecture

## Candidate unifying construct: State Transition Integrity
STI یک سازهٔ پیشنهادی برای آزمون است، نه نظریهٔ تثبیت‌شده.

ابعاد اولیه:
- Traceability
- Evidence Alignment
- Transition Stability
- Semantic Consistency
- Uncertainty Integrity

فعلاً نباید این ابعاد به یک امتیاز ترکیبی واحد تبدیل شوند تا اعتبار مستقل آنها آزموده شود.

## Cross-line connections
### ClaimLab / Epistemic Liquidity
Claim trajectory را به‌عنوان مسیر Observation → Inference → Explanation → Ontology مدل می‌کند. LEVELSHIFT و OVERCLAIM می‌توانند failure modeهای قابل تشخیص باشند.

### HHJ-CSG / Observable Decision Artifact
Epistemic Integrity از Decision Permission جدا می‌شود:
Evidence Integrity → Epistemic Assessment → Risk Assessment → Governance Decision.
ODA بر artifactهای قابل مشاهده مانند claim، evidence، tool event، confidence، decision، execution result و trace تکیه دارد، نه reasoning خصوصی.

### Provenance / Epistemic Distance
Epistemic Distance به‌صورت اولیه ClaimLevel − EvidenceLevel تعریف شده است. Provenance مبدأ و lineage را حفظ می‌کند؛ Liquidity حرکت و transformation را بررسی می‌کند.

### Replay
Replay فقط ابزار debugging نیست؛ می‌تواند object قابل اندازه‌گیری پژوهشی باشد: divergence، reproducibility، provenance completeness و behavioral integrity.

### Dynamic systems
P/S/T، LUMEN، market/streaming work و regime detection در سطح انتزاعی الگوی stream → memory → state estimate → transition/regime → action → feedback را نشان می‌دهند. این شباهت، اثبات یکسانی سازوکارها نیست.

### Rangāl / Nurgāl
می‌تواند به‌صورت آزمایشی به State Magnitude و State Change Rate نگاشت شود، مثلاً X(t) و dX/dt. این بخش تا زمان تعریف ریاضی و آزمون، formalism پیشنهادی است نه نظریهٔ علمی اثبات‌شده.

## Highest-information experiment
مقایسهٔ کنترل‌شدهٔ چهار ارزیابی:
- outcome-only
- confidence-only
- provenance-only
- explicit transition-integrity evaluation

سناریوها:
- valid evidence-aligned transition
- unsupported level jump
- provenance corruption
- semantic drift
- common-mode validator failure
- missing evidence
- contradictory evidence
- correct final outcome with incorrect transition

Ground truth باید قبل از اجرا مشخص شود.

## Falsification requirements
- baseline improvement باید مستقل از اطلاعات اضافی unfair باشد.
- shuffled/reordered trajectories باید آزمون شوند.
- provenance-complete-but-wrong باید وجود داشته باشد.
- correct-outcome/wrong-transition باید وجود داشته باشد.
- semantic drift باید مستقل از تغییر schema آزموده شود.
- common-mode corruption باید validators را به چالش بکشد.
- supporting experiment باید با failure-seeking experiment جفت شود.

## Evidence boundary
آنچه اکنون می‌دانیم:
- چند artifact و معماری واقعاً در repository پیاده یا ثبت شده‌اند.
- برخی مسیرهای replay/provenance و governance مهندسی شده‌اند.
- چند فرضیه دارای طراحی آزمایش و معیارهای falsification هستند.

آنچه هنوز نمی‌دانیم:
- آیا STI اطلاعات مستقلی فراتر از outcome/confidence/provenance می‌دهد.
- آیا شباهت معماری میان خطوط مختلف واقعاً یک abstraction عمومی است.
- آیا این ترکیب در ادبیات علمی قبلی کاملاً نو است.
- آیا formalism رنگال/نورگال قدرت پیش‌بینی یا توضیحی مستقل دارد.

## Priority-claim boundary
این repository به‌تنهایی تقدم تاریخی، «اولین بودن»، قانون علمی جدید یا اثبات فراهوش را ثابت نمی‌کند. هر ادعای novelty یا priority باید با prior-art/literature search مستقل بررسی شود.

## Research rule
هر ادعای مهم باید زنجیرهٔ زیر را داشته باشد:

Origin → Transformation → Evidence → Claim → Decision → Action → Outcome → Replay

و هر جا زنجیره قطع است، وضعیت باید UNKNOWN یا HYPOTHESIS بماند.
